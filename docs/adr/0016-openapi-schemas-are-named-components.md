# OpenAPI request and response schemas are named components

Every request body and every 2xx response body in the OpenAPI document is a `$ref` to a named schema in `components.schemas`, so Swagger UI lists them under **Schemas** and links each operation to its shape. A body's zod schema carries `.meta({ id })`: zod then emits it as a definition and `@nestjs/swagger` rewrites that into a component, so bodies need no extra code. Response schemas are hand-written `SchemaObject`s; a shared helper registers each under its name and returns its `$ref`, and `buildDocument` merges the registry into the components, as it already does for `Problem`. A list response refers to its element (`Vehicle`, `Action`) instead of repeating it. `/health/*` bodies stay inline, because Terminus owns them (ADR 0003), and query parameters stay `parameters`. A test fails when a body or 2xx response is inline or a `$ref` does not resolve. Every problem+json response carries an `example` built by `buildProblem` with its own status and code (`problemContent(status, code?)`): the shared `Problem` schema bounds `status` to 100–599, and without an example Swagger UI samples it as its maximum, so every error showed `599`. Rejected: hoisting inline schemas after the document is built (names would come from operation IDs, and a renamed handler would silently rename a schema) and DTO classes with `@ApiExtraModels` (ADR 0010 keeps the repo free of DTO classes). Amends ADR 0010, whose only hand-registered component was `Problem`; supersedes nothing.
