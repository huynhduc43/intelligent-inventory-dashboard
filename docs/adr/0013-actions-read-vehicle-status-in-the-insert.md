# Logging an action reads the vehicle's status in the same SQL statement

D5 allows actions only on an `IN_STOCK` vehicle, and §4.9 logs one with `INSERT INTO vehicle_action … SELECT … FROM vehicle WHERE id = $v AND dealership_id = $d AND status = 'IN_STOCK'`, then, on 0 rows, re-reads `vehicle.status` to choose 404 or 409. That is a read of `vehicle` from the `actions` module, which [ADR 0011](0011-inventory-reads-latest-action.md)'s list of named cross-table reads leaves out. We keep §4.9: `actions` reads `vehicle` only in read-only SQL (the `SELECT` inside its own insert and the re-read) and imports nothing from `inventory`, so it still writes only `vehicle_action`. The list of named reads becomes: `dashboard`; `inventory` list and detail → latest action; `actions` log → vehicle status. Asking `inventory` for the status first was rejected: it takes two statements, so a vehicle sold between them would still get an action, which is the race the conditional insert exists to close.
