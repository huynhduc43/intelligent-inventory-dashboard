# Make and model compare case-insensitively, with whitespace collapsed on write

The list filter matched make and model with `lower()`, while the dashboard grouped them as stored, so "Toyota Corolla" and "toyota corolla" were one list filter but two `byMakeModel` rows (#105, C22). The dashboard now groups by `lower(make), lower(model)`, the same expressions as the list filter and its index, and shows each group's most common stored spelling (ties go to the first in sort order). It groups the stored values first and folds case over those few groups, so `lower()` does not run on every row; `db:explain` showed per-row `lower()` doubling the statement's time at 16,000 in-stock vehicles. Intake trims make and model and collapses inner whitespace runs to one space, so "Land Rover" is stored as "Land Rover"; the list filters apply the same normalisation to their parameters. Migration `0002` backfills existing rows the same way. Case is still stored as entered. Rejected: normalising case on write by reusing an existing spelling per dealership. It fixes the stored data but adds a read before every insert, changes the intake contract, and needs a case backfill that has to pick a winner, for no visible gain over grouping case-insensitively. Supersedes nothing; amends §4.4's `GROUP BY make, model`.
