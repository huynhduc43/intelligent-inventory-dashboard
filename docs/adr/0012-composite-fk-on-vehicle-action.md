# `vehicle_action` references its vehicle through a composite foreign key

`vehicle_action` carries `dealership_id` and `vehicle_id` as independent columns, so nothing in the schema stopped an action from naming a vehicle of another dealership; only the service's `WHERE dealership_id = …` did. `vehicle` now has `UNIQUE (id, dealership_id)` and `vehicle_action` has `FOREIGN KEY (vehicle_id, dealership_id) REFERENCES vehicle (id, dealership_id)`, replacing the single-column foreign key on `vehicle_id`. The database now rejects a cross-tenant action even if a query forgets the filter. The extra unique index is the cost of the target key; `id` alone is already unique, so it adds no new rule. Applying the same pattern to other tables was not needed: `vehicle` and `user_dealership` reference only `dealership` and `app_user`.
