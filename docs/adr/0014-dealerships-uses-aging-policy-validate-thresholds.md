# `dealerships` validates thresholds with `AgingPolicy`; `inventory` does not depend on `dealerships`

P1 puts `validateThresholds` in `AgingPolicy` (`inventory/domain`), and §4.2 draws `inventory → dealerships`. The settings update in `dealerships` needs `validateThresholds`, so on paper the two would form a cycle. In the code the `inventory → dealerships` edge does not exist: `inventory` gets the thresholds, time zone and `todayLocal` from `DealershipGuard` in `auth`, which re-reads them on every request (D16), and imports nothing from `dealerships`. We keep P1: `validateThresholds` stays in `AgingPolicy`, and `dealerships` imports that pure function (and the `Thresholds` type) from `inventory/domain` and nothing else from `inventory`. The module edges become `inventory → auth` and `dealerships → auth`, `dealerships → inventory/domain`; there is no cycle. Moving the rule to `dealerships/domain` or to `shared` was rejected: it splits the aging rules across modules, and `shared` holds only infrastructure.
