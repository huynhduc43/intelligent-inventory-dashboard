# A dealership time zone must be a zone name in `pg_timezone_names` that is not also an abbreviation

P1 validates time zones against `pg_timezone_names`, and [ADR 0004](0004-text-check-and-app-side-timezone-validation.md) does it on write in `dealerships`. Some names in that view, such as `CET`, `EET`, `MET`, `WET`, `EST` and `UTC`, are also time-zone abbreviations, and `AT TIME ZONE` reads them as the abbreviation: a fixed offset with no daylight saving. A dealership stored as `CET` would get the wrong `todayLocal` for an hour each summer night, which is the error P1 exists to prevent. So the update accepts a name only on an exact, case-sensitive match in `pg_timezone_names` and no exact match in `pg_timezone_abbrevs`, in the same SQL statement as the write; anything else is `422 TIMEZONE_INVALID`. `Etc/UTC` is the accepted spelling of UTC. Catching SQLSTATE 22023 from `AT TIME ZONE` instead was rejected: it also accepts POSIX strings such as `UTC+5` (which means UTC−5), any case, and abbreviations.
